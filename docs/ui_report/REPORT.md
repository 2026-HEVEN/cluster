# HEVEN Cluster 차량 진단 화면 및 이력 그래프 개선 보고서

작업 기준일: 2026-09-10. 대상: Cluster ESP32 / 320×240 ILI9341 LCD.

이번 작업은 노트북 없이 차량 상태를 확인하도록 Car Check를 구성하고, 연결 이력과 최근 60초 그래프를 추가한 펌웨어 변경이다. 그래프를 열 수 있는 항목에는 `*`를 표시했다. 본 문서의 이미지는 **실제 펌웨어 화면 그리기 코드에 예시 데이터를 넣어 생성한 화면 미리보기**이며, 실차 측정 사진이나 실차 검증 결과는 아니다.

## 1. 무엇이 바뀌었나

| 항목 | 이전 로컬 구현 | 이번 변경 |
| --- | --- | --- |
| 기본 화면 | WSS 속도, 기어, HV SOC, HV/LV 전압, 랩 정보와 하단 Car Check 진입 칸 | 구분선과 Car Check 칸 제거, WSS 속도 확대, 상태 정보를 아래로 이동. 기어·HV SOC·HV/LV 전압은 화면 오른쪽 끝 기준으로 정렬 |
| 전력 표시 | POWER/CHARGE를 같은 방향의 막대로 표시 | 중앙 0 기준 양방향 막대. CHARGE는 왼쪽, POWER는 오른쪽으로 채워 방향을 즉시 구분 |
| GPS LAP 정지/재개 | Warning 중 단일 클릭으로 정지할 수 있으나 다시 이어서 시작하는 경로 없음 | 정지 후 단일 클릭하면 기존 기준점·결승선·랩 기록을 유지한 채 재개. 정지 시간은 랩타임에서 제외 |
| Car Check | 모터·전원·VCU·GPS 구분 | 최신 VCU 센서와 제어 적용 상태, 차단 이유를 세부 화면에 연결 |
| 그래프 접근 | 홈 화면 WSS 숫자 | 속도 숫자만 WSS 그래프로 연결하고, 나머지 홈 영역은 Warning 또는 Car Check로 연결. 세부 화면의 `*` 항목도 그래프 제공 |
| 저장량 | WSS 최대 20 Hz·10분, 가용 heap에 따라 최대 96 KB | 선택한 12개 수치 2 Hz·최근 60초, 고정 크기 RAM |
| 좌우 비교 | 개별 수치 확인 | 버스 전류·상 전류·버스 전압을 같은 그래프에 표시. L 점선 / R 실선 |
| 통신 진단 | 현재 LIVE/WAIT 확인 | 연속 연결 시간, 단절 횟수, 모터 고장 발생/해제 이력 |
| 화면 갱신 설정 | 약 15 Hz | 50 ms / 20 Hz 목표 |
| LV SOC | 공급 데이터 없음 | 막대와 %를 만들지 않고 LV 전압만 표시 |
| 상세 화면 행 | 화면별 구분 방식이 달랐음 | 모터·전원·VCU·센서·GPS 화면의 데이터 행 구분선을 제거해 통일 |

CAN bitrate는 250 kbps이며 기존 BMS/GNSS/Lap 송신 주기는 유지한다. 화면 갱신 설정을 올렸다고 원천 센서의 측정률이 올라가는 것은 아니다. 실제 LCD 갱신률과 BLE·Wi-Fi 동시 동작 부하는 실물에서 확인해야 한다.

## 2. 화면 이동

기본 화면에서 **큰 속도 숫자 영역을 누르면 WSS 그래프**가 열린다. 속도 영역을 제외한 나머지 화면을 누르면 경고가 있을 때 Warning 이유 화면으로, 경고가 없을 때 Car Check로 이동한다. 별도의 작은 `CAR CHECK` 버튼을 찾을 필요가 없도록 홈 화면 대부분을 진입 영역으로 사용한다. Car Check의 네 영역은 모터, 전원, VCU·센서, GPS·RTK이다.

세부 화면에서 `*`가 붙은 항목을 누르면 해당 그래프가 열린다. 오른쪽 위 `BACK`은 그래프를 열었던 화면으로 돌아간다. GPIO13 순간버튼은 어느 화면에서나 기본 화면으로 돌아가는 HOME 기능을 유지한다. 화면 하단 `LINKS / HISTORY`에서 연결 상태와 이벤트 이력을 확인한다.

| 화면 | `*`로 표시한 그래프 항목 |
| --- | --- |
| 모터 상세 | BUS V, BUS A, PHASE A. L/R 같은 그래프 |
| 전원 | BMS VOLTAGE, EM HV VOLTAGE, EM LV VOLTAGE, EM HV CURRENT |
| VCU | THROTTLE, WSS REPRESENTATIVE |
| GPS | FIX / RTK |

홈 화면에서는 WSS 숫자만 그래프로 연결한다. 스로틀 그래프는 VCU 세부 화면의 `THROTTLE *`에서 연다. 조향·IMU·온도·RPM은 이번에 이력 저장 대상으로 추가하지 않았으므로 별표가 없다.

GPS LAP 버튼의 단일 클릭은 더블클릭 판별을 위해 약 320 ms 뒤 처리한다. 처음에는 유효한 GPS Fix 위치를 Start/Finish로 설정하고 `LAP START SET`을 표시한다. Warning 상태에서 실행 중인 랩을 단일 클릭하면 `LAP STOPPED`, 정지 상태에서 다시 단일 클릭하면 `LAP RESUMED`를 표시한다. Resume 시 기존 기준점, 가상 결승선, 완료 랩과 현재 랩 경과시간을 유지하며 정지해 있던 시간은 제외한다. 320 ms 이내 빠른 더블클릭은 기존과 같이 `GPS LAP RESET`을 표시하고 기준점·결승선·모든 랩 기록을 초기화한다.

## 3. 각 화면 미리보기

### 기본 화면

구분선과 하단 Car Check 칸을 없애고 WSS 속도를 3자리 기준 14배 글꼴로 확대했다. 기어, `HV SOC`, 게이지, %, HV/LV 전압은 화면 오른쪽 끝을 동일 기준으로 정렬했다. 속도 아래의 스로틀·브레이크·전력 막대와 랩 정보는 남은 하단 공간으로 내려 배치했다. 스로틀은 VCU가 보낸 유효한 %를 사용한다. 브레이크 압력은 아직 수신 항목이 없어 `BRK --`와 빈 외곽선으로 표시하며, 이는 압력이 0이라는 뜻이 아니다.

![기본 화면](ui_home.png)

전력은 동일한 EM RECORD의 HV 전압과 전류로 `|V×I|/1000`을 계산하여 kW로 표시한다. 숫자는 THR/BRK와 같이 막대 왼쪽에 두고, 막대는 위 두 게이지와 같은 시작점과 폭으로 정렬했다. 막대 아래에는 왼쪽부터 `CHR / 0 / PWR`을 배치한다. 중앙 `0`을 기준으로 **회생 충전(CHARGE)은 왼쪽**, **구동 전력 소비(POWER)는 오른쪽**으로 채워진다. 각 방향은 10 kW를 가득 찬 상태로 표시하며, 10 kW를 넘어도 숫자는 실제 계산값을 계속 표시한다. 현재 임시 방향 규칙은 **EM 전류가 0 이상이면 POWER, 0 미만이면 CHARGE**이다. 실차에서 알려진 구동·회생 조건과 비교해 부호가 반대라면 이 매핑만 뒤집으면 된다. 이는 규정 충족 여부를 판정하는 기능은 아니다.

![네 영역 메뉴](ui_menu.png)

모터 상세와 다른 상세 화면의 시각 구조를 통일하기 위해 데이터 행 사이의 가로 구분선을 제거했다. 제목 아래 기준선, `BACK` 버튼 외곽과 하단 `LINKS / HISTORY` 경계는 탐색 구조를 구분하기 위해 유지한다.

![GPS 상세](ui_gps.png)

### 연결 업타임과 발생 이력

LIVE 옆 시간은 **현재 연결이 연속으로 유지된 시간**이다. 연결이 복구되면 다시 0부터 센다. `D`는 연결 단절 횟수, `F`는 새로 켜진 모터 고장 비트의 누적 횟수이다. 아직 한 번도 연결되지 않은 항목은 WAIT이며, 부팅 직후 미연결 상태를 반복 단절로 세지 않는다.

![연결 상태 첫 페이지](ui_links.png)

![연결 상태 두 번째 페이지](ui_links_2.png)

최근 32개 이벤트를 RAM에 보관한다. 최초 연결, 단절, 복구, 모터 고장 발생과 해제를 시각과 함께 표시한다. 시각은 전원 투입 이후 경과시간이다. 저장 한도를 넘으면 가장 오래된 이벤트를 덮어쓰고 `overwritten` 수를 표시한다. 전원을 끄면 초기화되며 상용 ECU의 영구 고장 코드 저장을 대체하지 않는다.

![발생 이력](ui_events.png)

고장 프레임을 받지 못하는 동안에는 고장이 해제되었다고 기록하지 않는다. 다음 유효한 프레임이 들어온 뒤 해제 여부를 판정한다. 단절과 고장은 별개이므로 D/F도 별도로 센다. F는 현재 모터 고장 비트를 대상으로 하며, 다른 장치의 모든 고장까지 수집하는 기능은 아니다.

## 4. 최근 60초 그래프

숫자 이력은 500 ms마다 한 번 저장한다. 화면을 열지 않아도 기록하며, 열린 동안에도 계속 최신화한다. 저장 범위를 최근 60초로 제한했으므로 60초보다 오래된 기록을 스크롤해 조회하는 기능은 이번 버전에 없다. 장시간 분석은 TMA-1 로그를 사용한다.

상단 NOW 또는 L/R 숫자는 최신 상태를 사용한다. 2 Hz 그래프는 추세 확인용이며 짧은 전류 피크나 빠른 제어 응답을 검증하는 계측 로그가 아니다. 유효하지 않은 구간은 선을 끊고, 연결이 끊긴 값을 0으로 보간하지 않는다.

좌우 비교는 동일한 시간축·단위를 사용한다. L은 점선, R은 실선이다. 두 값이 일치하면 선이 겹칠 수 있으며, 임의로 위치를 어긋나게 표시하지 않는다. 상단 숫자로도 좌우 값을 비교할 수 있다. 전압 그래프는 작은 변화를 보기 위해 관측 전압 주변으로 세로축을 확대하므로, 왼쪽 축의 실제 범위를 함께 읽는다.

## 5. LV SOC 막대를 만들지 않은 이유

현재 EM은 HV 전압·HV 전류·LV 전원 전압·CPU 온도를 보낸다. HV SOC도 EM이 아니라 BMS BLE에서 받는다. LV 배터리는 별도이며 현재 LV SOC를 제공하는 수신 항목이 없다.

LV 전압은 표시할 수 있지만, 그것만으로 실제 잔량 %를 결정할 수는 없다. 배터리 화학계·직렬 수·부하·온도 등의 영향을 받으며 현재 검증된 전압-SOC 관계나 LV 전류 적산 입력도 없다. 따라서 **HV에는 SOC 막대/%를 표시하고, LV에는 전압만 표시한다.** LV SOC 표시에는 별도 LV BMS의 SOC 또는 검증된 잔량 추정 체계가 필요하다.

## 6. 추가 CAN 정보 및 팀별 확인 사항

세부 전달문은 [추가 CAN 정보 및 실차 확인 사항](CAN_DATA_REQUIRED.md)에 별도로 정리했다.

- VCU: 실제 브레이크 압력 측정 및 CAN 정의가 필요하다. 이미 정의된 Steering/IMU/개별 WSS/제어 상태는 새 송신 요청 대신 차량 업로드 버전과 해석 기준을 확인한다.
- 전원/EM: 전류 부호, 설치 위치, LV 측정 지점, 실차 송신 주기, 충전 막대 기준을 확인한다.
- TMA-1: 새 센서·제어 상태, valid/life, EM RECORD/SYNC를 기존 decoder와 대조한다. Decoder 생성만으로 실차 수신 검증이 완료되는 것은 아니다.

## 7. 코드 변경과 검증

화면은 순수 렌더링 모듈, 이력은 고정 크기 저장 모듈, 실제 상태 연결은 `check_snapshot.cpp`로 나눴다. CAN 수신부에는 VCU Car Check v1 디코더를 추가했다. 기존 동적 WSS 기록 버퍼를 고정 이력 버퍼로 교체하고, 화면 갱신 태스크를 50 ms로 설정했다. LCD 전송 중 한꺼번에 들어오는 프레임을 보관하도록 CAN RX 대기열을 SDK 기본 5개에서 64개로 늘렸다. 글꼴에는 `*`, `>`, `?`, `|`, `_`를 추가했다. GPS 랩타이머에는 정지 시점의 경과시간과 출발 대기 상태를 저장하는 Pause 상태를 추가하고, Resume 시 랩 기준 시각을 보정하도록 변경했다.

주요 파일: `src/modules/diagnostics.*`, `diagnostic_graph.cpp`, `diagnostic_home.cpp`, `diagnostic_history.*`, `car_check_receiver.*`, `src/core/check_snapshot.*`, `src/core/app_wiring.cpp`, `src/core/can_bus.cpp`, `include/state.h`, `include/car_check_protocol.h`, `src/logic/font5x7.cpp`.

검증 결과: 전체 native 테스트 **110개 통과**, 이 중 새 진단 기능 테스트 **26개 통과**. ESP32 빌드도 성공했다. 정상·미수신·끝값 및 그래프를 포함한 27개 화면 이미지를 생성하고 빈 화면 여부, 별표와 터치 대상 일치, BACK 버튼, 행 구분선 제거, 양방향 전력 막대의 좌·우 채움 및 배치를 확인했다.

| 메모리 항목 | 확인값 |
| --- | --- |
| ESP32 고정 이력 저장부 | 9,400 B, 약 9.2 KiB |
| 숫자 샘플 | 12개 수치 × 최대 121시점, valid 및 단절 표시 포함 |
| 이벤트 | 최근 32개, 전원 종료 시 초기화 |
| RTK 상태 변화 | 최대 256개, 최근 60초 상태를 표현할 기준점 포함 |
| 전체 정적 RAM | 80,564 B / 327,680 B, 24.6% |
| Flash | 1,096,517 B / 1,310,720 B, 83.7% |

정적 RAM 수치는 BLE·Wi-Fi와 CAN 대기열 등의 실행 중 heap 사용량을 포함한 전체 최고 사용량이 아니다. 기존 최대 96 KB 동적 WSS 버퍼 할당은 제거했다. 이력 크기는 컴파일 시 10 KiB 이하 조건으로 검사한다. D/F 카운터의 내부 누적값은 유지하고 화면에서는 999를 넘으면 `>999`로 축약한다.

실차에서의 터치 좌표·가독성, 실제 표시 주기, BLE/NTRIP 병행 안정성, 모터·EM 전류 부호는 별도 확인 대상이다. 이번 작업은 로컬 코드와 문서 작성까지이며 실기기 업로드 및 GitHub 게시는 실행하지 않았다.
